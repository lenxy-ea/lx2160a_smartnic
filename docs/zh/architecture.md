# 架构

X200 启动链为 PBL → RCW/PBI → TF-A BL2 → TF-A BL31 → 原生 U-Boot →
Linux → Debian。板级配置由本仓库源码维护；固定版本的 NXP 依赖提供通用
SoC 实现和工具。

## 硬件配置

公开硬件契约位于 `bsp/lx2160-x200/hardware-evidence-v1.json`，定义 RCW/PBI、
TF-A、U-Boot、DPC、DPL 和 Linux 设备树使用的板级事实。配置必须绑定相应
fact ID。配置检查验证这些绑定关系，不代表完成了新的硬件测量。

仓库只包含当前维护的板级配置，采用 DDR3200 和 SerDes2 protocol 5。
PCIe3 配置上限为 Gen3 x4；连接实际设备后的链路协商尚未完成验证。

## 存储与启动职责

两个 NOR 是独立寻址的 16 MiB 器件，每个镜像有独立布局和完整性元数据，
不能拼接为一个 Flash 地址空间。U-Boot 在启动前校验所选组件组合。
校验和用于发现损坏，不提供启动认证。

TF-A 负责 DDR 初始化。U-Boot 负责固定 SATA 启动策略，并加载当前 NOR 内的
MC 固件、DPC、DPL 和设备树。SATA 分区 1 存储启动文件与内核，分区 2 存储
Debian。构建与打包命令只生成普通文件，不写入物理磁盘。

NOR 环境区保留运行时启动偏好。板卡 MAC 从 SoC UID 派生。系统配置保存在
SATA 上。板载 EEPROM 不用于 BSP 内容、配置或身份存储；DDR SPD 与 SFP
识别属于独立接口。

## PCIe 管理与网络

Linux 完成控制器初始化后发布 PCIe5 管理端点。配套的主机和板卡模块、服务
建立管理网络。主机网卡选择、地址、路由、DNS 和可选 NAT 均由使用者配置。

产物身份由构建程序生成。打包程序消费构建清单并验证实际内核和模块，使用
build ID、文件哈希、模块 vermagic 和导入符号 CRC 防止混用不同构建产物。

NetworkManager 负责系统网络配置。运行服务负责各自的 PCIe 发布生命周期，
并保持正确的停止顺序。安装与目标激活由使用者显式执行。

## 开发边界

本仓库包含产品源码、测试、依赖版本与产品文档，构建不依赖外部板级研究归档。
生成文件保存在 `build/`。新增硬件敏感配置必须更新对应契约，不能用参考板
默认值代替 X200 的硬件事实。
